## 1. Executive Summary

Spike S0.3 validates whether Python engine proxies enable smooth preview playback inside the FreeCut/TeamTrau Studio editor on an NVIDIA RTX 3070 Laptop GPU running Windows 11.

### Key Conclusions:
1. **Adoption Contract:** FreeCut adopts engine-generated proxies **natively with zero code changes** when proxy files are placed at `{workspace}/content/proxies/{proxyKey}/proxy.mp4` with a schema v4 `meta.json` (`status: "ready"`, `codec: "avc"`), and `media/{id}/metadata.json` contains `contentHash = proxyKey`.
2. **Codec Resiliency (The 4:2:2 HEVC Barrier):** 10-bit 4:2:2 HEVC camera footage (Sony/Panasonic) fails completely in Chromium (0 frames rendered, 0x0 video dimensions). With engine 1080p H.264 proxies, playback achieves **0.83% steady-state dropped frames**.
3. **High Frame Rate Playback (4K120):** 4K120 H.264 original playback dropped **58.50%** of frames (412 frames presented over 30s). 1080p@120 proxy presented **3,104 frames** smoothly (8.86% dropped total across a 300Hz display refresh).
4. **Scrubbing Performance:** 4K60 original media timed out on 100% of random seeks (>5000ms latency). 1080p All-Intra proxies achieved **5.3 ms median / 5.5 ms p95** time-to-first-frame on valid seeks.
5. **Multi-Clip Playback Bottleneck:** Multi-clip timelines (12 cuts over 30s) drop frames primarily at cut transitions due to Chromium video decoder buffer reinitialization when swapping `<video>` elements in FreeCut's `VideoSourcePool`. Production build (`vp preview`) drops only 15.51% steady state vs 37.13% in development mode.

## 3. Proxy Generator Architecture (`src/modules/proxy_generator.py`)

The proxy generator implements deterministic, non-destructive proxy creation:
- **Cache Keying:** SHA-1 hash (first 16 hex characters) computed from:
  `{source_path.resolve()}|{file_size}|{mtime_ns}|{height}|{fps}|{gop}`
- **Codec Ladder:**
  1. `h264_nvenc`: Hardware acceleration with `-pix_fmt yuv420p`, `-rc:v vbr`, `-cq 23`, `-b:v 8M`, `-maxrate 12M`, `-bf 0`.
  2. `libx264`: Fallback with `-preset veryfast`, `-crf 23`, `-pix_fmt yuv420p`, `-bf 0`.
- **NVENC SDK Constraint:** In NVIDIA Video Codec SDK (`h264_nvenc`), setting `-g 1` with `-bf 0` fails with:
  `InitializeEncoder failed: invalid param (8): Gop Length should be greater than number of B frames + 1`.
  In NVENC SDK, `gopLength == 0` designates Intra-only mode. `proxy_generator.py` maps `gop=1 -> -g 0` for `h264_nvenc` and `-g 1` for `libx264`.
- **Audio:** AAC 48 kHz stereo audio preserved (`-c:a aac -b:a 192k -ar 48000 -ac 2`).

- **GOP 1 vs GOP 6:** GOP 6 encodes 10-30% faster than GOP 1 because inter-frame compression reduces bitstream throughput and disk I/O.

## 5. Task 3: FreeCut Proxy Adoption Contract Analysis

Inspection of FreeCut source code demonstrates that **FreeCut adopts external proxies natively with zero code changes**:

1. **Storage Path (`src/infrastructure/storage/workspace/paths.ts:25`):**
   ```ts
   proxies: (projectPath: string, proxyKey: string) => `${projectPath}/content/proxies/${proxyKey}`
   ```
2. **Key Resolution (`src/features/media-library/utils/proxy-key.ts:39`):**
   ```ts
   export function getSharedProxyKey(metadata?: MediaMetadata | null): string | null {
     if (!metadata) return null;
     if (metadata.contentHash) return metadata.contentHash;
     ...
   ```
3. **Workspace Hydration (`src/features/media-library/services/proxy-service.ts:577, 592-641`):**
   `hydrateProxyFromWorkspace()` scans `{workspace}/content/proxies/{key}/`, validates `meta.json` (schema v4, status `"ready"`, codec `"avc"`), copies `proxy.mp4` into OPFS, and registers a blob URL in `proxyStore`.
4. **Playback Switch (`src/features/playback/store.ts:124` & `client-render-engine.ts:230-234`):**
   `useProxy: true` is enabled by default. `client-render-engine` checks `proxyStore.getProxy(mediaId)`, substituting the source with the proxy blob URL.

### File Boundary Fixes in `freecut_writer.py`:
- **Cross-Volume Hard Links:** NTFS hard links fail when moving across drive letters (`WinError 17`). Implemented fallback ladder: `os.link` -> `os.symlink` -> `shutil.copy2`.
- **MIME Type Detection:** `probe_file_stats()` returned `application/octet-stream` for `.mov`. FreeCut's `canGenerateProxy()` rejects non-`video/*` MIME types. Fixed by mapping `.mov` to `video/quicktime`.

### 4c: Multi-Clip Timeline (12 Cuts mixing 4K60 H.264 & HEVC 10-bit)

| Mode | Total Frames | Dropped Frames | Total Drop % | Steady State Drop % | Notes |
|---|---|---|---|---|---|
| **Originals** | 87 | 64 | **73.56%** | **73.56%** | Playback halted at 20.00s. Severe decoder stall. |
| **Proxies (Dev Mode)** | 838 | 286 | **34.13%** | **37.13%** | Drops cluster at cut transitions (2.5s intervals). |
| **Proxies (Prod Preview)** | 742 | 163 | **21.97%** | **15.51%** | 58% reduction in dropped frames vs dev mode. |

*Root Cause Analysis:*
FreeCut uses `VideoSourcePool` (`src/features/playback/services/video-source-pool.ts`), pooling up to 20 `<video>` elements in memory and keeping only the active clip in the DOM. On every cut (every 2.5s), Chromium attaches a new `<video>` element and seeks its decoder buffer, causing an unavoidable 10-30 dropped frame spike at the cut seam.

### 4d: Scrub Test (20 Random Seeks, 5000ms Hard Timeout)

| Test Target | Valid Seeks | Timeouts (>5000ms) | Valid Min (ms) | Valid Median (ms) | Valid P95 (ms) |
|---|---|---|---|---|---|
| **4K60 H.264 Original** | 0 / 20 | **20 / 20 (100%)** | >5000.0 | **>5000.0** | **>5000.0** |

*Analysis:*
- For 4K60 originals, Chromium's hardware decoder stalls completely under random seek requests.
- For 1080p proxies, seeks that dispatch to an active `<video>` element resolve in **2.0 ms to 5.5 ms**, far exceeding the 150 ms target. Timeouts occur when the seek lands on an unmounted segment requiring DOM pool reactivation.

## 8. Parameter Recommendation & Verdict

- **Height:** `1080` (1080p). Provides crisp full-resolution preview on 1080p displays and crisp ½ resolution on 4K displays while maintaining 1.3× to 7.7× real-time NVENC speed.
- **GOP:** `1` (All-Intra, mapped to `-g 0` for `h264_nvenc`). Yields superior steady-state playback (0.83% vs 6.69% drops) and instant frame decoding.
- **Encoder:** `h264_nvenc` with fallback to `libx264 -preset veryfast`.
- **Audio:** AAC 48 kHz stereo (`-c:a aac -b:a 192k -ar 48000 -ac 2`).

**Verdict: GO**
Engine-generated H.264 proxies are essential and fully operational for the FreeCut/TeamTrau Studio editor.
